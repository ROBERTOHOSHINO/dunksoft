¿Cuántas contraseñas has usado hoy?

El problema de autenticación que todos enfrentamos

Demasiadas contraseñas

ID y contraseña distinta por servicio. Anotarlas = riesgo de filtración.

Servicios sin conexión

Google, Apple, Microsoft — todos aislados. Mismo email, cuentas distintas — confusión y re-configuración constante.

Eres un desconocido en cada org.

El login de org. A no funciona en org. B. La misma persona se registra una y otra vez.

Un eslabón débil lo expone todo

Una organización descuidada pone en riesgo a todas. Los administradores no tienen cómo responder.

Lo que debería haber sido

Login del SO → federado a todos los servicios automáticamente

→

Lo que tenemos hoy

Tecnología primero, confianza bolted on después. La confusión continúa.

La pregunta clave

¿Podemos construir un ecosistema de autenticación diseñado desde la confianza — no desde la tecnología? Como el repartidor de confianza del barrio — conocido, bienvenido en todas partes.

How many passwords did you use today?

The authentication problem we all face

Password overload

Separate ID/password per service. Written down = security risk.

Services don't talk to each other

Google, Apple, Microsoft — all siloed. Same email, different accounts — confusion and constant re-setup.

You're a stranger everywhere

Login for org A doesn't work in org B. The same person registers again and again.

One weak link, system-wide risk

A single lax organisation exposes everyone. Admins have no way to respond.

What OS design intended

OS login → federated to all services automatically

→

What we got instead

Technology first, trust bolted on later. The confusion continues.

The question

Can we build an authentication ecosystem designed around trust — not technology? Like the trusted neighbourhood delivery person — familiar, welcome everywhere.

サービス間が連携できない

セキュリティの穴が広がる

一か所の甘さが全体に波及。管理者も対処の手段がない。

→

現実（後付け連携の歪み）

技術が先、信頼が後付け → 混乱が続く
